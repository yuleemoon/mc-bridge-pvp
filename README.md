# 我的世界 · 桥战 PvP

一个纯静态、单文件的 Minecraft 风格 1v1 桥战小游戏。红蓝双方在 1 格宽的窄桥上对决，可用剑近战、弓远程，也可用方块搭桥过缺口、筑墙挡箭；掉出桥面即坠入虚空。**先到 5 杀获胜**。支持两种模式：**本地同屏双人** 与 **WebRTC 点对点联机**（房间码匹配）。

- 零依赖构建：双击 `index.html` 即可本地游玩
- 可直接部署到 GitHub Pages（详见下方部署步骤）
- Three.js + PeerJS 均走 jsDelivr CDN（版本固定），音效为原生 WebAudio 合成，无任何图片/音频素材

## 玩法要点

- 窄桥（1 格宽）上设有多处缺口，含一处双格大缺口：可助跑跳过，也可用方块搭桥
- 每名玩家有 40 个方块，向前放置可搭桥，向面前上方放置可筑墙挡箭
- 剑：近战 16 伤害，带击退——把对手击落桥面也是致胜手段
- 弓：远程 9 伤害，抛物线弹道，带少量击退
- 坠入虚空或生命归零都会阵亡，1.6 秒后于己方出生点复活（带 1.5 秒免伤闪烁）
- 掉虚空且近期被攻击时，击杀记在攻击者名下

## 本地运行

直接双击 `index.html`，用 Chrome / Edge 等现代浏览器打开即可（首次加载需联网获取 Three.js CDN）。

## 联机对战（WebRTC 点对点）

1. 在开始菜单点 **联机对战** → **创建房间**，生成 6 位房间码
2. 点 **复制邀请链接** 发给好友；好友打开链接即自动匹配进房，也可手动输入房间码点 **加入房间**
3. 双方连接成功后自动进入 3-2-1 倒计时并开战：**房主固定红方 P1，加入方固定蓝方 P2**
4. 局中 HUD 会显示实时网络延迟（ms）；掉线时自动弹提示并返回菜单
5. 对局结束（先到 5 杀）可点 **再来一局**（对手同步重开）或 **返回菜单**

> **测试建议**：两台设备联网对战体验最佳。若只用一台电脑开两个标签页测试，浏览器会把后台标签页降频——已内置后台保活机制（模拟、快照、输入持续流动，不会被冻结），但后台一方的画面帧率会下降，属浏览器自身限制。

## 部署到 GitHub Pages

1. 在 GitHub 新建仓库（例如 `bridge-duel`），把本目录的 `index.html` 和 `README.md` 推上去：

   ```bash
   git init
   git add index.html README.md
   git commit -m "我的世界桥战 PvP"
   git branch -M main
   git remote add origin https://github.com/<你的用户名>/bridge-duel.git
   git push -u origin main
   ```

2. 进入仓库 **Settings → Pages**，Source 选择 `Deploy from a branch`，Branch 选 `main`、目录 `/ (root)`，保存。

3. 等待一两分钟，即可通过 `https://<你的用户名>.github.io/bridge-duel/` 访问游戏。

> 提示：若要部署到「用户名.github.io」根路径，请把 `index.html` 放到以用户名为名的仓库根目录，访问地址即为 `https://<你的用户名>.github.io/`。
>
> **联机说明**：联机依赖 PeerJS 公共信令（0.peerjs.com），需要 **HTTPS 环境**——GitHub Pages 自带 HTTPS，部署后即可联机；本地双击打开（file://）通常也能连，但部分网络环境可能受限。**公网（两台设备在不同网络）**：P2P 直连靠 PeerJS 内置 STUN 打洞，多数家用宽带可直连；严格对称 NAT（部分移动网络/企业网）会打洞失败、卡在「正在匹配主机」，此时建议两台设备连同一 WiFi/热点测试，或更换网络。PeerJS 公共信令不含 TURN 中继，无兜底。

## 技术说明

- 单文件自包含：CSS、JS、Three.js 场景、WebAudio 音效、PeerJS 联机层全部内联，便于静态托管
- Three.js 版本固定为 `0.158.0`（jsDelivr CDN）；该版本会打印一条 UMD 弃用提示，属预期——Three.js 从 r160 起移除了 UMD 构建，此处固定版本不受影响
- 联机同步采用**主机权威**：房主本地模拟双方物理与战斗，按 15Hz 下发状态快照 + 事件（伤害/击杀/放方块/音效）；访客按 15Hz 上报输入意图，本地各自跑模拟保手感（低延迟预测），命中与放置方块等判定以房主为准，访客做视觉修正
- 房间码 ID 使用确定性 Peer ID（`bridge-v2-<房间码>-host/guest`），公共信令无自建服务器成本；丢包场景下以最新快照为准

## 已知边界

- 必须使用键盘，触屏设备只能观看/转视角
- 联机为点对点，双方网络质量直接影响体验（HUD 有延迟显示）；公共信令偶尔波动时重试即可
- 公网联机受 NAT 类型影响：对称 NAT（部分移动/企业网络）可能打洞失败连不上，优先同 WiFi 或热点
- 同一浏览器开两个标签页对战时，后台标签页会被浏览器降频（帧率下降），已做保活处理但体验仍不如两台设备
- 本地打开与部署后功能一致，无服务器依赖（联机仍需联网）
